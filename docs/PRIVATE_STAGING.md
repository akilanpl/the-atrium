# Private staging preparation — milestone 06

Templates are not a deployed or tested host. No hosting credentials/authorized staging endpoint were supplied. Do not expose dev ports, incur infrastructure costs or change repository visibility.

## Operator procedure

1. Use a dedicated HTTPS hostname behind the reviewed VPN/access gateway or the nginx template's tester Basic authentication. Provision a unique password per tester in `/etc/nginx/atrium-testers.htpasswd`, outside the repository. Use an approved secret channel, revoke departing testers. Basic authentication requires HTTPS and cached same-origin authorization for WebSocket upgrades; verify in every supported browser. Invitations remain separate game authorization. Disable public origin access at firewall. Robots headers are supplementary, never an access control.
2. Pin a reviewed commit, `npm ci`, run `npm run release:check`, `npm run typecheck:browser` and the full browser matrix. `npm run build` produces client dist and compiled server. Keep immutable `/srv/atrium/releases/<sha>` directories and an atomic `current` symlink. Install a supported Node runtime at the service's configured path.
3. Configure a root-owned `/etc/atrium/staging.env`: NODE_ENV=production, TLS_PROXY=1, PORT=2567, ALLOWED_ORIGINS exactly the HTTPS origin. Omit FAST_MODE and custom timers. The source does not load .env. Build frontend with default same-origin WSS. Never put secrets in VITE variables.
4. Install the systemd template with a restricted atrium user, memory/task/FD limits and read-only filesystem. Start backend only behind loopback/firewall. Serve only client dist. Validate compiled entry path after each build. Run `nginx -t` before reload; certificate paths/hostname/access file must exist. Require the authentication gateway for API and WebSocket routes as well as HTML/assets.
5. Disable query/body/access tracing in nginx, upstream, CDN and monitoring. Colyseus upgrade URLs carry transient credentials. Verify actual logs after create/join/recover, redact credentials, and define short retention/access controls. Process logs should contain only allowlisted counts/events. Monitor sanitized health, RSS, restarts, rejected connections, CPU and event-loop lag; set operator alerts using measured thresholds.
6. Verify HTTPS/WSS, proxy upgrades, exact/bad Origin, CSP asset/script/connect behavior, HSTS, no-index, tester access rejection, denied /matchmake, no source/.env/maps/dev tooling, payload/connection limits and no direct backend access. Local `/health` and `/ready` are for a loopback supervisor; do not publish detailed monitoring endpoints.
7. Run six independent browser sessions through the gateway, full hiding/rotation/revisit/portal/replay, drop/refresh in each phase and host handoff. Run bounded churn/slow-consumer/expiry tests with consent. Validate SIGTERM draining and a restart. Restart intentionally loses in-memory rooms; notify testers first.
8. Rollback: stop admission, notify testers, record sanitized incident details, stop service, atomically select the prior reviewed release, restart and probe loopback readiness and authenticated browser join. Retain the prior lockfile/build; do not overwrite or force-push Git history. Document the release SHA, operator and actual results.

Required before PRIVATE STAGING READY: full green browser/physics/security CI, live authenticated TLS/CSP/proxy/firewall/logging checks, approved tester access, monitoring/rollback rehearsal, operator/privacy contacts and representative device/network testing. None of the live-host checks is claimed by supplying these templates.
