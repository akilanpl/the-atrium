# Architecture — milestone 05

`packages/shared/src/universes.ts` is the registry for six IDs, names, physics profiles, bounds, spawn points, five anchors per world, mechanisms, colliders and six-door placement. MIN_PLAYERS, MAX_PLAYERS and MAX_UNIVERSES are separate constants. A crypto-seeded shuffle assigns unique universes; the fixed participant order produces N−1 distinct opponents without self-assignment.

`packages/shared/src/physics.ts` steps body position, velocity, grounding and environment forces. The server Game owns fixed-step simulation, mechanism states, placement, deadlines, rotation, inventories and atomic portal victory. `index.ts` adapts private Colyseus admission, strict message schemas, 20 Hz simulation and personalized 10 Hz snapshots. Only loaded connected visitor instances advance; each visitor has an independent puzzle copy.

The wire movement contract is bounded `input {epoch,seq,x,z,yaw,run,jump,descend}`. It contains no coordinates or forces. Old `move` requests are rejected by runtime validation. Epoch changes on replay, sequence numbers reject stale packets, and a 250 ms deadman clears abandoned input. Critical interactions validate phase, world, target, 3D distance, plausible line of sight, permissions, availability and mechanism gates. See PHYSICS.md for model limits.

Preparation messages are hide/place, edit, variant, decoy, undo, reset and ready {clue}. Hide starts a server clock; place needs a matching approved anchor after a 600 ms hold. The socket cannot submit an arbitrary ready-anchor. Props use three approved slots, variants two states, decoys two harmless anchors, history ten entries. Ready validates the selected anchor, bounded mechanism transitions, navigation and traversal feasibility, then seals editing. Creator-only workshop state disappears after preparation. Seekers receive their clue, timed hints and own mechanism state, not the hidden anchor. Private-world rival transforms are redacted. Final explicit anchor hints are intentional overtime disclosure.

`World.tsx` lazy-loads scenery and coordinates lighting, audio, avatar interpolation, frame samples and scene disposal. Library retains existing licensed props. Five small scene entry modules share original procedural environment geometry. `Interactions.tsx` renders targets and mechanism feedback; `spatialInteraction.ts` selects the center-camera ray target within reach and occlusion limits. Server authorization is independent of that visual targeting.

`Controls.tsx` sends input at 20 Hz and interpolates authoritative transforms, retaining orbit/zoom, obstruction handling, vertical camera following and text-focus guards. `Character.tsx` retains skeleton cloning, animation and eyelid lifecycle. No client prediction or replicated bones. `main.tsx` supplies invitation flow, creator tools, progress, clues, moderation, fair results and replay. Settings retain LOW/MEDIUM/HIGH, audio and navigation aids.

Security/admission remain in security.ts/index.ts: private HTTP authorization, one-use grants, exact HTTP/WS origins, cryptographic invitations/recovery, bounded rate/resource maps, TTLs and graceful shutdown. See SECURITY_ARCHITECTURE.md. In-memory single-process rooms require sticky routing and disappear on restart; distributed persistence is not implemented.
