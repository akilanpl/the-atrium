# Security architecture

## Admission and identity
The browser posts a strict `{create,invite,name,avatar}` body to `/api/admit`. The server creates a private Colyseus room using a process-only creation credential, or redeems a 256-bit random invite against the server registry. The public Colyseus HTTP router is denied by an outer path allowlist. Neither room IDs nor nicknames authorize entry. The admission route obtains a 10-second seat reservation and installs a cryptographically random one-use grant. Static `onAuth` checks the process-only admission authority and supplies a random 256-bit seat identity, replacing the framework default length. `onJoin` consumes the one-use grant from server-side reservation options. Reservation/session identifiers are transient bearer material: protect the whole connection with TLS.

Invites expire after 30 minutes. Host replacement deletes the old entry immediately. Host locking refuses new admissions; existing reserved seats have at most 10 seconds to finish joining. Kicking closes the target, excludes reconnect grace and rotates the invite. Existing participants may still copy an invite they knew: this is private link-based admission, not verified real-world identity. Do not share invitations publicly. Optional host approval is not implemented.

Colyseus 0.17 `onDrop` / `allowReconnection(20)` / `onReconnect` preserve the original seat. Explicit departure, kick, flood closure, expiry and room disposal reject recovery. `POST /api/reconnect` validates a bounded credential and asks Colyseus to validate its 256-bit recovery token (rotated on join/reconnect); it never creates a new identity. A tab stores its recovery token in sessionStorage for refresh, never localStorage. Storage denial degrades refresh recovery without preventing play. Automatic reconnect buffers zero gameplay commands. Client-side credentials are accessible to same-origin JavaScript; CSP and dependency hygiene remain essential. This is not account authentication.

## Transport and resource limits
Exact origin allowlists apply before HTTP routing and during actual WebSocket upgrade. Missing Origin is denied on POST and upgrades; nonbrowser clients can forge Origin, so invite/seat authorization is still required. Production configuration rejects HTTP origins, FAST_MODE and missing TLS proxy declaration. Listener is loopback only. Express does not trust forwarded IP headers. The proxy applies edge IP limits; backend limits are deliberately aggregate behind a local proxy. No horizontal scaling is supported.

Limits: HTTP body 2 KiB; socket payload 2 KiB; 40 HTTP requests/IP/minute; 30 upgrades/IP/minute; 70 application messages/seat/second, eight non-movement actions/seat/second and 80 raw protocol messages/seat/second; six seats/room; 100 rooms/process; 512 TCP connections; limiter maps at most 4096 entries, expiring after their window; seat grants 10 seconds; invites 30 minutes; rooms at most one hour. Ping every 10 seconds with two missed responses before termination. Snapshot writes close slow consumers above 64 KiB buffered data. Room timers and disposal clear room resources. Hard caps protect this process, not an internet link against volumetric attacks.

## Authorization and integrity
Every message is an explicit allowlisted schema with unknown fields rejected. The server derives identity from the admitted socket. Host-only actions: start, replay, invite replacement, join lock and kick. The Game enforces phase, owner, known destination, object proximity, collision segment travel, per-player mechanisms, independent key copies and key deduplication. Movement now uses server-owned 20 Hz bounded-input simulation, epoch/sequence replay rejection and a deadman timeout; finish prevents further movement/search and first portal winner is atomic in this single event loop. Client-supplied awards, phases, speeds, identities and winners are rejected. Hidden anchor/secret maps never enter snapshots. Each recipient receives only its assigned clue and its own mechanism state; key counts remain shared game information; private-world rival transforms are redacted.

## Text, reports and logs
Nicknames/clues require bounded NFKC-normalized plain text; controls, bidi formatting and angle brackets are rejected. React text rendering remains in use. Reports contain bounded IDs and an enum only, at most 32 records/room, deduplicated per reporter/target/reason and deleted within 10 minutes (or disposal). Host gets an immediate moderation notice; reports are not a staffed central moderation service. Players can hide the clue locally and leave.

Server logs are sanitized event categories and minute aggregate room/invite/RSS/denial/flood counts. They omit names, IPs, bodies, invites and puzzle secrets. Upstream errors are reduced to transport categories. Colyseus necessarily uses ephemeral session/reconnect credentials in WebSocket upgrade query strings: the supplied proxy disables access logs and strips forwarded identity headers. This protocol exception must be tested on the actual hosting platform; do not enable URL/body logging or traces. No application database, persistent match history or analytics is introduced.
